Systems & tools

The bank upload now refuses the wrong file
We found out why a batch of junk rows appeared in the ledger back in May: a Capital One statement had been uploaded into the Citizens box. The two files share only one column name, so everything else came in blank. There is now a check that recognises which bank a file came from by reading the file itself, and refuses it with a plain message instead of importing it quietly. It works in both directions, and if it does not recognise a file at all it lets it through untouched, so it can never block the daily reconcile. It is in place but not yet loaded into the running screen, so it starts protecting uploads from the next restart, not from today.
One tool now answers the duplicate-charge question
Two earlier reviews of the same month's duplicate charges came back with two different totals, which is worse than either answer, because there is no way to tell which one to trust. There is now a single tool that answers the question the same way every time, by reusing the very same rules the bank import uses rather than a second copy of them. Checking it against both earlier reviews showed that neither of their totals held up, and that the gap between them was a difference in method rather than missing money. The tool has since been found to have a blind spot of its own, which is the next thing to fix.
A written plan for the rest of this work
The backlog of these system items has been sorted into nine groups, in the order they are worth doing, each with an estimate of how long it takes and a note on how it would be done. That ordering had only ever been discussed out loud, so it existed nowhere and would have been lost. It is now written down.
